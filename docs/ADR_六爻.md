## D1 · 只做客观描述，不输出吉凶断语

**背景**
测事体系的公理 A5「生克中性」——生克本身无吉凶，吉凶来自问事者的立场。同一组卦象，
问「该不该做」和问「会顺利吗」，结论可以完全相反。软件无从知道问事者的完整语境。

**决策**
分析层输出**整卦五型 / 半卦五型 / 八步流程 / 四层框架 / 宫位趋势 / 飞伏 / 转太极**的客观链路与状态标注，
但**不下**「成 / 不成」「吉 / 凶」「该 / 不该」的机器判定。文本中不出现「大吉」「大凶」等断语。

**理由**
- 模型无法持有问事者的价值函数；替人下结论就是把信息量替换成噪声。
- 软件的价值在**穷尽人容易漏看的维度**（伏神、暗动、月破、本变五型、转太极），而非替代裁决。

**影响**
四层框架的第二层命名为「成败层 —— 五项链路**事实**检查」，第四层「吉凶层」只罗列世爻位置、
六神、空破墓、宫位走向等事实素材。测试 `run_tests.js` 有断言守住这条线。

**状态**：已采纳（v0.1.0）

## D2 · 六亲一律以**本卦卦宫五行**为基准

**背景**
六亲（父母/兄弟/子孙/妻财/官鬼）需要一棵「以谁为我」的参照系。流派有两种口径：
以世爻为我，或以日干为我。本体系定义层明文写的是**卦宫**。

**决策**
`liuqinOf(本卦卦宫五行, 该爻地支五行)`。**变爻的六亲也用本卦卦宫**（身份不变），
但能量取变后新支（能量可换）。

**理由**
- 卦宫是卦的先天身份，与问事者当下状态无关 → 六亲结构在同一卦内恒定，可复现、可核对。
- 世爻会因卦而变（世在几爻取决于八宫序），日干每日一变 —— 都不适合当结构基准。
- 变爻若改按变卦卦宫定，会出现「同一爻位在两个六亲身份之间跳变」，破坏八步流程的连续性。

**影响**
全 64 卦 × 6 爻 = 384 个六亲位有唯一解；测试逐项校验。伏神同样按本卦卦宫判定缺哪一亲。

**状态**：已采纳（v0.1.0）

## D3 · 与文档 §3.8 案例的冲突 —— 按明文规则（卦宫）实现，不按案例

**背景**
方法论文档 v2.1 §3.8「天风姤找伏神」案例中，以**日干甲木**为我来定六亲，得出
「兄弟不上卦，伏神寅木为兄弟」。这与同文档定义层「六亲以卦宫五行定」直接冲突。

**决策**
以**定义层明文**为准：姤属乾宫（金），故 父母丑戌、子孙亥、兄弟申酉、官鬼午，
**妻财不上卦**，伏神取乾为天二爻 **甲寅木 · 妻财**。

**影响**

## D5 · 月建冲静爻：日冲=暗动，月冲=月破（都标注）

**背景**
文档 §3.6 写「日辰或月建冲静爻均为暗动」；传统六爻作「日冲为暗动、月冲为月破」。
两者对同一爻的判读不同（暗动 = 能主动发力；月破 = 根基受损）。

**决策**
日冲静爻 → `暗动`（可发力，等同动爻）；月冲静爻 → `月破`（标注受损）。两者在盘面上都显示标签。

**理由**
- 传统口径对「月冲」的处理有更强的一致解释：月令为一月之气候背景，冲的是**根基**；
  日辰为当日之气，冲的是**状态**。混为一谈会让「月破」这个概念在体系里无处安放。
- 两种冲都**如实显示**，读者两种口径都能看到，不隐藏信息。

**影响**
`computeState` 中 `y.dark`（日冲）与 `y.yuepo`（月冲）分别建模；`yaoTag` 分别渲染。
**若邦顺判定月冲亦为暗动，只需在 `y.dark` 的判据里加上 `y.chongYue`。**

**状态**：待裁（当前按传统口径实现）

## D6 · 强弱计权：克我 −2，其余 ±1

**背景**
「强弱」是把日令与动爻对某爻的生克合成一个净额，需要一个显式计权表才能被核对。
传统口诀（如「用得生为旺，受克为衰」）不给数值。

**决策**

| 作用 | 计权 |
|---|---|
| 生我 | +1 |
| 同类比和 | +1 |
| 我生（泄） | −1 |
| 我克（耗） | −1 |
| 克我 | **−2** |

**理由**
- 克是直接夺气（压制/否定），泄与耗是被动流失，量级不同。把克我记为 −2 后，
  「一个动爻来克我」就能把平爻（0）直接压到弱（−2），符合断事直觉。
- 显式化后，软件能把每一条加减的来源打印成注记（如「日令午 火 克我」），
  读者可逐条核对，而不是接受一个黑箱标签。

**影响**
`strengthOf()` 的 `apply()` 函数；标签阈值 ≥2 / 1 / 0 / −1 / ≤−2。
**ADJUST 入口**：只改 `strengthOf` 一处，八步流程与四层框架自动跟随。

**状态**：已采纳（v0.1.0）

## D7 · 取卦只用摇卦（时间起卦 / 报数起卦下线）

**背景**
v0.1.0–v0.1.1 提供三式取卦：手动录入六爻、时间起卦、报数起卦。邦顺指出：
「事情不可能只有一个变化，有时无，有时有，有时多，有时少。而时间、报数都是一个变爻，
这是不符合事实的。请将起卦方式，改为摇卦。」

**决策**
取卦收敛为**摇卦**一种：自下而上摇六次，每次三枚钱（三正 = 老阴(动)、二正一反 = 少阴、
二反一正 = 少阳、三反 = 老阳(动)）。六爻各自独立，动爻数完全由摇得 ——
0 个（六爻全静）、1 个、多个乃至六个都可能。
删除 `qiguaByTime`、`qiguaByNumber`、`bitsFromTrigrams`、`XIAN_TIAN`，
以及只服务于时间起卦的农历表 `src/tables/lunar.js`。

**理由**
- 时间起卦（梅花定式）与报数起卦都是「以确定输入反推上卦/下卦/动爻」，动爻由 `mod 6` 得出，
  **恒为一个动爻** —— 结构上排除了「无变化」与「多个变化」两种真实情况。
- 摇卦的每一次投掷独立，动爻数是摇出来的、不是算出来的，与「变化可有无、可多少」同构。
- 取卦方式的自由度一旦被算法钉死，往下的变卦、化进化退、回头生克等整条判断链都会随之失真。

**影响**
- `src/d_engine.js`：删除两式取卦与相关常量；`zhuangGua(bits, states, cal)` 仍以 states 为唯一真相源。
- `src/f_ui.js`：模式切换（`S.mode` / `setMode` / tabs）移除，摇卦录入成为唯一输入区；
  盘面顶部新增「摇卦记要」（本次摇得几个动爻）。
- 测试：删三式断言，新增「摇卦 0–6 动爻」穷举断言（543 → 558 条）。
- 农历表随之下线；节气表保留（四柱仍按节气）。

**状态**：已采纳（v0.1.2）

## D8 · 页面代掷（电子摇卦）—— 字面的另一个来源，不改规则

**背景**
D7 之后取卦只剩摇卦，输入依赖现实中的三枚铜钱。邦顺提出：
「你要模拟摇卦的过程来起卦。」—— 手边无铜钱、或想连掷带录一步完成时，需要由页面完成投掷。

**决策**
录入区提供**页面代掷**：三枚铜钱各掷一次、六次独立，单次 / 连摇两个入口，每次投掷的钱面逐条留痕。
代掷与手动录入**等价**：它只决定「字面」，装卦、状态层、八步断事仍走同一条路，不引入额外规则。

- 四象口径与手动录入一致：三正 = 老阴 6、二正一反 = 少阴 8、二反一正 = 少阳 7、三反 = 老阳 9。
- 随机源：`crypto.getRandomValues`（不可预测），取不到时退回 `Math.random`；每枚钱独立取值、等概率。
- 可复现：钱面逐条写在录入区，凭记录重新录入即得同一卦。
- 记要标注来源：六爻皆由代掷得来 →「摇卦（页面代掷）」；手动改过任何一爻 →「摇卦」。

**理由**
- 代掷只是把「三枚钱的字面」这一环节交给页面，动爻数依旧是掷出来的，D7 的结构不变。
- 不用代掷时，手动录入完全保留 —— 现实中摇过的卦照旧可以逐爻录进。

**影响**
- `src/d_engine.js`：新增 `triaState(coins)`（字面 → 爻）、`tossTria(rng)`、`defaultRng()`。
- `src/f_ui.js`：录入区新增代掷区块（摇一次 / 连摇六次 / 清空重摇 + 钱面记录）；`S.tossCoins` 记录每爻来源。
- 测试：新增代掷段（映射穷举、随机源调用次数、分布、0–6 动爻覆盖、与手动录入等价），558 → 578 条。
- 时间起卦、报数起卦仍不在列（D7 不变）。

**状态**：已采纳（v0.1.3）

爻级已有虚实四态（值空/值破/入墓 × 旺衰），得失分析的半卦面板只到「整旺衰」为止，
邦顺看不到半卦本身的虚与实，五型作用（如「金生水」）是实生还是虚生无从判断。

**决策**
halfLevel 的 side() 同构爻级口径输出 `xs`（实／虚／半实半虚／半虚半实）＋`xsNote`＋`broken`：
值空＝日空支含半卦五行；值破＝月冲/日冲支含半卦五行；入墓＝墓库为月/日支。
**半卦无动静爻，故不设爻级「动而逢冲」类前提**，月破日破一律成立；月空不参与（Q6 已销案＝D16，判定层只走日空）。
真假空与入墓/入库随旺衰分野（旺＝假空/入库＝待时，衰＝真空/入墓＝无力）。
pair() 在本侧 broken 时给该侧五型标 `mdFake`（作用不实），呈现为中列「（作用不实）」小字；
虚实作为属性面板第八项（5 行布局末行左列）。

**理由**
- 半卦是五行对象不是爻对象，判定只能落在五行层可观察的事实上（空/冲/墓/旺衰），不能虚构动静。
- 与爻级完全同构，四态与真假口径无需新学——一套体系贯穿四层对象。

**影响**
得失分析每卡多一行虚实、中列可能带作用不实小字；测试 +4 条（四态卦例锁定）；
四层判定重组（todo #6）时半卦「实生/虚生」可直接消费 `broken`/`mdFake`。

**状态**：已采纳（v0.1.61 实现并断言锁定；月空参与与否已由 Q6 销案定案＝D16）。

## D16 · Q6 销案：月空维持仅标注，判定层一切空亡口径走日空

**背景**：Q6 自 v0.1.33 挂起（月空是否参与真空假空／暗动／旺衰／出空应期判定）。2026-10-05 第45轮邦顺查算法后按推荐销案。

**决策**：月空（月柱旬空 `mkong`）**维持仅标注**，不参与任何判定——真假空、暗动、旺衰、虚实四态、
出空填实应期等一切空亡口径仍只走日空（`cal.kong`）。理由：传统六爻主流只论日旬空；
月空判定属少数派口径，无体系资料支撑其参与方式；现有判定层自洽无缺口。

**影响**：引擎零改动；待裁清单 Q6 销案（Q7 应期尺度仍挂）；变爻/伏神空标仍只判日空（同口径）。

**状态**：已采纳（v0.2.14 文档轮，产物指纹不变）。
